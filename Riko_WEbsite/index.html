↗

First-time setup needs internet. Installers create or reuse .venv-tts, install dependencies, download Kokoro assets, prepare Ollama with qwen3:4b-instruct, warm the Faster-Whisper base cache and launch profile setup if no personal profile exists. Profile saving requires confirmation.

⌁

Windows: the installer can use winget for missing Python, Ollama or curl. Desktop and Start Menu shortcuts launch the GUI without a console.

!

Linux: setup uses sudo (or root) with apt-get and automatically configures Debian/Ubuntu only. If a Kokoro download fails, a .part file may remain in models/kokoro/; inspect or remove it before retrying. Reruns are not failure-proof.

▤

Local files stay local. Model assets and personal profiles are created on your machine and are not committed to the repository.

PRIVACY BY DEFAULT

Local-first.
With clear limits.

RIKO keeps its default conversation path on your machine. Here is what that does—and does not—mean.

01

Conversations stay local

Chat sessions, personal profiles and the optional speech cache live on your machine. Default setup sends prompts and messages only to the local Ollama HTTP service at 127.0.0.1:11434, and configures no hosted LLM API.

02

No persistent chat history store

The active conversation is held in process memory for the running session only.

03

Git-ignored local configuration

Personal preferences, persona choices, behaviour overrides, speech-cache files and profile data live under config/local/ and are not committed.

04

Local diagnostic logging

Logs are written under logs/ and record timing, event information, error details and some tool-call metadata. Review local logs before sharing them.

05

Setup is not offline

Dependencies and model assets are downloaded during installation. Local-first inference does not make the installation offline.

06

Bounded tools

The codebase explorer is read-only and excludes sensitive paths, environment files, binary files, model files, logs and virtual environments. This is a safety boundary for that tool, not a security audit of the machine.

PROJECT STATUS

What works today.

Active development. Features, interfaces and setup requirements may change.

WORKING TODAY CURRENT
  • Desktop GUI (Tkinter) on Windows and Linux, with an OS-native title bar, and an equivalent terminal mode
  • Text chat with Markdown replies, streaming, Regenerate and Read aloud
  • Hands-free voice mode with Kokoro speech and interruption controls
  • Local Faster-Whisper transcription with rolling drafts and a two-minute limit
  • CLI menu: Text Chat, Voice Chat, Settings and Selectors, Exit
  • Stop control that cancels the active Ollama stream and Kokoro playback
  • Local profiles, eleven behaviour parameters, and response-style presets
  • Zoom from 80% to 160% via controls, shortcuts and mouse wheel
  • Two bounded local tools: architecture lookup and read-only source explorer
ROADMAP IN PROGRESS

Desktop GUI (GTK4) — in progress

Growth mode and voice barge-in tuning — in progress

!

Prototype, not promise.

Voice interruption is a prototype. Acoustic echo cancellation is not implemented, so headphones are recommended. Barge-in and echo behaviour depend on the microphone, speakers, room and audio drivers.

Model outputs can be inaccurate. A 4-billion-parameter model running locally can produce plausible but incorrect statements.
